## 2. Root Cause Analysis: KPI (5.02 MT) vs Narrative (56.10 MT)

### The Problem
In earlier builds, querying *"What was GEVRA's production in FY2024-25?"* resulted in an apparent contradiction:
- KPI Card: `Actual Production = 5.02 MT`, `Target = 5.00 MT`, `Achievement = 100.40%`, `Variance = +0.02 MT`
- Narrative / Report Citation: `Actual Production = 56.10 MT`, `Target = 58.50 MT`, `Achievement = 95.90%`, `Variance = -2.40 MT`

### Investigation & Boundary Trace
1. In PostgreSQL, `production_annual` stores two sets of rows:
   - Initial pre-hackathon seed rows (`DEOM-01`, `KNUG-02`, `SSOP-03`). For DEOM-01 in 2024: actual was `5.02 MT`.
   - Authoritative 5 canonical mine rows (`GEVRA`, `KUSMUNDA`, `DIPKA`, `NIGAHI`, `DUDHICHUA`). For GEVRA in 2024: actual is `56.10 MT`.
2. When querying `DeterministicQueryService.get_annual_production(mine_code="GEVRA")`:
   - `_get_mine_aliases("GEVRA")` resolved to `['DEOM-01', 'GEVRA']`.
   - SQL query applied `WHERE mine_code IN ('DEOM-01', 'GEVRA') ORDER BY mine_code`.
   - Alphabetically, `'DEOM-01'` was sorted first and returned as row index 0.
   - The frontend `/ask` page bound `facts[0]` (`actual_production_mt = 5.02 MT`), rendering `5.02 MT` in the primary KPI cards.
   - Concurrently, Qwen and vector document RAG retrieved GEVRA annual reports citing the true canonical figure of `56.10 MT`.

### The Boundary Fix
1. In `DeterministicQueryService.get_annual_production`:
   - When a canonical mine code is queried (`GEVRA`, `KUSMUNDA`, etc.), filter **strictly** by `ProductionAnnual.mine_code == canonical_code`. Never fall back to legacy aliases when canonical records exist.
   - In multi-mine comparison queries without a specific `mine_code`, filter specifically by the 5 canonical mines: `['GEVRA', 'KUSMUNDA', 'DIPKA', 'NIGAHI', 'DUDHICHUA']`.
   - Legacy alias resolution is preserved exclusively for legacy tests that explicitly request legacy mine identifiers (`DEOM-01`).
2. Result: Both `facts[0]` and narrative now report the identical, authoritative values:
   - Actual Production: **56.10 MT**
   - Target Output: **58.50 MT**
   - Achievement: **95.90%**
   - Variance: **-2.40 MT**

## 4. Qwen Reasoner & Deterministic Fallback Upgrades

### System Prompt & Context Formatting ([backend/app/ai/qwen_reasoner.py](file:///F:/GeoVault/backend/app/ai/qwen_reasoner.py))
- Instructs Qwen3-8B to output strictly two sections: `SUMMARY:` followed by `DETAILED ANSWER:` with markdown `###` headings.
- Enforces canonical units: **1 MT = 1 Million Tonnes** (never confuse MT with metric tonnes or write 56,100 MT).
- Mandates clear separation between:
  - **MEASURED FACTS** (database numbers)
  - **SOURCE OBSERVATIONS** (document report citations)
  - **ANALYTICAL INFERENCES** (contextual interpretations)
- Increased `max_tokens` to `600` to prevent narrative truncation.

### Upgraded Deterministic Fallback Generator
Even if local Qwen inference times out on CPU hardware, `_generate_fallback_deterministic_summary` deterministically outputs the exact two-part format with markdown headings, verified numbers, and provenance notices:
- Single Mine: `### Production Performance`, `### Target Comparison`, `### Interpretation`, `### Evidence & Provenance`.
- Multi-Mine: Markdown comparison table with Actual, Target, Achievement, Variance across all 5 canonical mines.
- Spatial: `### Spatial Analysis`, `### Identified Features & Distances`, `### PostGIS Calculation Details`.
- Geology: `### Geological Findings` with stratigraphic seam thickness, dip, continuity, and quality band.
